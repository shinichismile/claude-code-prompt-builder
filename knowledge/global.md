世界中の研究・実践から蓄積された主要なプロンプト技術集。
研究論文・実務・海外コミュニティで検証済みの手法のみ収録。

## 1. Chain of Thought (CoT) — 思考の連鎖

**出典**: Google Brain研究チーム（2022）/ 世界最も引用されるプロンプト手法の一つ

**概要**: AIに思考過程を段階的に書かせることで、最終回答の精度を上げる。

**基本形**:
```
この問題を解く前に、考え方をステップバイステップで書いてください。
その後、最終回答を出力してください。
```

**Few-shot CoT（例を使う高度な形）**:
```
例: 15個のリンゴを3人で分けると1人何個？
考え方: 15 ÷ 3 = 5。なので1人5個。

では: 24個のオレンジを4人で分けると1人何個？
考え方:
```

**効果が高いタスク**: 数学・論理・コードデバッグ・複雑な分析・法的判断・医療診断

## 2. Tree of Thought (ToT) — 木構造思考

**出典**: Princeton & Google 研究チーム（2023）

**概要**: 複数の思考経路を同時に探索し、最良の解を選ぶ。行き詰まったら別の枝を試す。

**使い方**:
```
以下の問題について、3つの異なるアプローチを考えてください。
各アプローチを100字程度で説明し、それぞれの長所と短所を評価してください。
最後に、最も優れたアプローチを選び、その理由を述べてください。
```

**効果が高いタスク**: 戦略立案・創作・設計・複数の解が存在する問題

---

## 3. ReAct (Reasoning + Acting) — 推論と行動の統合

**出典**: Google & Princeton 研究チーム（2022）

**概要**: 「考える → 行動する → 観察する」を繰り返す。ツール使用や実際の操作が伴うタスクに最適。

**パターン**:
```
Thought: [次に何をすべきか考える]
Action: [ツールを使う・コードを書く・検索する]
Observation: [結果を確認する]
Thought: [次のステップを考える]
...
Final Answer: [最終回答]
```

**Claude Code / Cowork向け応用**:
```
タスクを進める際、以下のサイクルで進めてください：
1. Thought: 何をすべきか考える
2. Action: ファイルを読む / コードを書く / コマンドを実行する
3. Observation: 結果を確認する
4. 必要に応じて繰り返す
5. Final Answer: 完成した結果を報告する
```

## 4. Self-Consistency — 自己一貫性

**出典**: Google Research（2022）

**概要**: 同じ問題に複数の方法でアプローチさせ、共通する結論を最終回答とする。

**使い方**:
```
この問題に3つの異なる方法でアプローチしてください。
それぞれの方法で答えを出した後、共通する結論を最終回答として述べてください。
```

**効果**: 単一回答より正確性が上がる。特に重要な判断・分析に有効。

## 5. Zero-shot / Few-shot / Many-shot の使い分け

| 状況 | 手法 | 例の数 |
|------|------|--------|
| 汎用的・シンプルなタスク | Zero-shot | 0個 |
| 特定フォーマットが必要 | Few-shot | 1〜3個 |
| 専門的・複雑なタスク | Few-shot + CoT | 2〜5個（思考過程含む） |
| 高精度が必要な反復タスク | Many-shot | 10〜20個 |
| 全く新しいタスク | Few-shot必須 | 2〜3個 |

**重要**: 例の質は量より大事。1つの完璧な例は、5つの雑な例より効果的。

## 6. System / User / Assistant の構造的分離

AIとの対話を3層に分けて設計することで、再利用しやすいプロンプトになる。

```
[System] — 変わらない設定（役割・制約・全体方針）
  ↓
[User]   — 毎回変わる入力（具体的な指示・データ・質問）
  ↓
[Assistant Prefill] — 出力の書き出し（フォーマット強制）
```

**実践例**:
```
System:
あなたはプロの翻訳者です。常に自然な日本語に翻訳し、
翻訳後に原文との差異があれば注記してください。

User:
以下を翻訳してください：
"The quick brown fox jumps over the lazy dog."
```

**メリット**: Systemを一度書けば、Userだけ変えて何度でも再利用できる。

## 7. ペルソナパターン（Persona Pattern）

**概要**: AIに詳細なキャラクター・専門家像を与える。役割だけでなく思考プロセスまで定義する。

**弱いペルソナ（効果薄）**:
```
あなたはエンジニアです。
```

**強いペルソナ（効果大）**:
```
あなたはGoogleで15年働いたシニアソフトウェアエンジニアです。
コードレビューでは以下の優先順位で確認します：
1. セキュリティリスク（最優先）
2. スケーラビリティと設計
3. パフォーマンス
4. 可読性とメンテナンス性

指摘するときは「なぜ問題か」と「どう改善するか」を必ずセットで伝えます。
```

**定義すべき要素**: 職歴・専門分野・思考の優先順位・コミュニケーションスタイル・価値観

## 8. プロンプトチェーン設計パターン（Prompt Chaining Patterns）

複雑なワークフローを分割して連鎖させる3つの主要パターン。

**逐次チェーン（Sequential）**: 前の出力を次の入力に渡す
```
ステップ1: 要件整理 → [要件リスト]
ステップ2: [要件リスト]を元に設計 → [設計書]
ステップ3: [設計書]を元に実装 → [コード]
```

**分岐チェーン（Conditional）**: 条件によって異なるプロンプトへ
```
入力を分類する → [技術的質問 / 一般的質問 / クレーム]
  技術的質問 → 技術サポート用プロンプト
  一般的質問 → FAQ用プロンプト
  クレーム   → クレーム対応用プロンプト
```

**並列チェーン（Parallel）**: 複数タスクを同時実行して統合
```
同時実行:
  エージェントA: コードを書く
  エージェントB: テストを書く
  エージェントC: ドキュメントを書く
→ 統合: すべての成果物をレビューしてまとめる
```

## 9. 出力制御テクニック（Output Control Techniques）

**長さ制御**:
- 「簡潔に」→ 効果薄
- 「3文以内で」「200字以内で」→ 効果的

**形式強制**:
- JSON出力: Prefillに ` ```json\n{` を使う
- 表形式: 「Markdownの表形式で出力してください」
- 番号付きリスト: 「1. 2. 3. の番号付きリストで」

**否定指示の回避**:
- 「〜しないでください」→ 効果薄い場合がある
- 「代わりに〜してください」→ より確実

**言語固定**:
```
【重要】回答は必ず日本語で出力してください。
```
→ 最後に追加すると確実性が上がる。

## 10. メタプロンプティング（Meta-Prompting）

**概要**: AIに「より良いプロンプトを作って」とお願いする手法。このスキル自体がメタプロンプティングの応用。

**基本形**:
```
以下のプロンプトをより効果的に改善してください：
[既存のプロンプト]

改善のポイント：
- より明確な役割設定
- 具体的な出力形式の指定
- ハルシネーション防止の制約追加
```

**逆用（プロンプトを最初から作ってもらう）**:
```
私は[目的]を達成したいです。
このためにClaudeに渡す最適なプロンプトを作ってください。
以下の要素を含めてください：役割設定・コンテキスト・手順・出力形式・制約
```

## 11. 構造化プロンプト（Structured Prompting）

海外の上級者が使う、プロンプトを構造化して管理する手法。

**RISEN フレームワーク**（世界的に普及）:
```
Role    : [役割]
Input   : [入力・コンテキスト]
Steps   : [手順]
Expectation: [期待する出力]
Narrowing: [制約・絞り込み]
```

**CO-STAR フレームワーク**（シンガポール GPT-4 大会優勝者考案）:
```
Context    : 背景情報
Objective  : 目標・目的
Style      : 文体・スタイル
Tone       : トーン・口調
Audience   : 対象読者
Response   : 出力形式
```

## 世界の第一人者たちの共通ルール

1. **具体性が命** — 曖昧さゼロ。数字・形式・条件で具体化
2. **役割を与える** — 専門家ペルソナで品質が劇的に向上
3. **例を見せる** — 百聞は一見にしかず。1例でも大きく変わる
4. **分割統治** — 複雑なタスクは小さく分けてチェーンする
5. **思考を外に出す** — CoTで思考過程を書かせると精度が上がる
6. **繰り返し改善** — 完璧なプロンプトは一発では生まれない
7. **制約を必ず入れる** — ハルシネーション防止は必須
8. **出力形式を明示する** — 「良い感じに」は通じない
